# ASCIIは打てるのに日本語入力だけができない（imeElからフォーカスが外れる）

## 症状

ターミナルへ英数字は打てるしキーバインドも効くのに、日本語入力へ切り替えると変換候補ウィンドウも
未確定の下線も出ず、ローマ字がそのままPTYへ送られる。ポップアップ（`niwaterm popup lazygit`等）を
開くと直る。macOS・Windowsのどちらでも起きる。

発生条件はまちまちで、起動直後とは限らない。

## 原因

niwatermはキー入力を2系統で受けている。

- ASCIIとキーバインド → `document`レベルの`keydown`
- 日本語入力 → 不可視のtextarea（`#ime-input`）に来る`composition`イベント

前者はフォーカスがどこにあっても動くのに対し、**Chromiumは編集可能要素にフォーカスが無いと
OSのIMEを無効化する**。そのため`#ime-input`からフォーカスが外れると、後者だけが死ぬ。
ポップアップを開くと直るのは、表示時の処理がフォーカスを入れ直すため。

## フォーカスが迷子になる経路

`#ime-input`を指すフォーカスは、次のような経路で簡単に外れる。個別のイベントごとに
`focus()`を呼び直す作りでは塞ぎきれない。

1. `mousedown`の既定動作が、フォーカス不能な要素のクリックでフォーカスをbodyへ落とす
   （[起動直後にキー入力が届かない・クリック後も日本語入力だけできない](/known-issues/windows-startup-webview-focus-and-ime.md)）
2. 「対象が変わらないなら何もしない」形の早期returnを通ると、`focus()`の行まで到達しない。
   サイドバーの行クリックのように、クリック自体はフォーカスをボタンへ移してしまう操作で問題になる
3. Radixのダイアログ・メニューは閉じるときにトリガー要素へフォーカスを戻す。この復帰は
   こちら側の`focus()`より後に走ることがあり、その場合は上書きされる
4. フォーカス中の要素がrenderでの差し替えごと消えると、`focusout`すら飛ばないまま
   `document.activeElement`がbodyになる

## 対処

個別の`focus()`は残したうえで、フォーカスの迷子をmainview側で一元的に拾い直す
（`src/mainview/ime-focus.ts`）。判定のきっかけは2つ。

- `focusout`の後（Radixのフォーカス復帰とrenderが落ち着いてから判定するため1タスク遅らせる）
- ターミナルへ届く打鍵のたび（経路4のように`focusout`が飛ばない場合の保険）

奪い返してはいけないのは次の3つで、いずれも判定から除外する。

- 入力欄・ダイアログ・メニューの中にフォーカスがある（URL欄やコマンドパレットの検索が打てなくなる）
- テキスト選択が残っている（textareaへフォーカスを移すと選択が消え、コピーが空振りする）
- このwebviewがキーボードフォーカスを持っていない（他アプリやブラウザタブの操作を邪魔する）

## 切り分けの進め方

DOM上のフォーカスとOSキーボードフォーカスは別物なので、`document.activeElement`だけでなく
`document.hasFocus()`も必ず併記して見る。前者だけを見ていると、webviewがそもそも
キーボードフォーカスを持っていないケースと区別できない。
