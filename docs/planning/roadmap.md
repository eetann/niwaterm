## シェルプロファイル選択（複数シェル・WSLディストロ対応）

Windows TerminalやWeztermのように、新規タブ作成時に起動するシェルを選べるようにしたい（Windows Terminalの「+」ボタン横の「⌄」ドロップダウンが参考UI）。
WindowsのWSL環境では複数ディストロ（Ubuntu・NixOSなど）が同居することもあるため、それも選択肢に含めたい。

プロファイル一覧の管理方式は「自動検出＋config併用」を採用する。Windows起動時に`wsl.exe --list --quiet`相当でインストール済みディストロを自動検出してプロファイル化し（PowerShellは常に固定プロファイルとして追加）、`niwaterm.config.ts`ではSSH先などの追加分だけ書けばよい設計にする。全プロファイルを毎回手で列挙する静的方式は、WSLディストロが増減するたびに設定ファイルの更新が要るため採用しない。

プロファイル配列・WSL自動検出・タブ作成時の選択UIまで実装済み（詳細: docs/guide/config.md「シェルプロファイル」節、docs/guide/cli.md）。WSL自動検出・ドロップダウンUIともにElectrobunがLinux非対応でこの開発環境（WSL）では動かせないため、Windows実機での動作確認は未実施（コード・ユニットテストレベルでの検証のみ）。

- [x] 設計: プロファイル管理方式を検討し、「自動検出（Windowsは`wsl.exe --list`相当）＋config.ts併用」方式を採用する
- [x] `niwaterm.config.ts`に`shell.default`を追加し、新規タブ作成時のデフォルトシェルを設定できるようにする（PTY起動への配線・ホットリロード対応まで完了。ユニットテストで検証済み。詳細: docs/guide/config.md「シェル設定」節）
- [x] 複数プロファイル（PowerShell・各WSLディストロ・SSH先など）を`shell.profiles`配列で管理できるようにする
- [x] Windows起動時にインストール済みWSLディストロを自動検出し、profilesへマージする（`wsl.exe --list --quiet`の出力はUTF-16LEになりうる既知の挙動に対応。Windows実機での最終確認は未実施）
- [x] タブ作成時にプロファイルを指定できるようにする（RPC `newTab`・IPCサーバー`/new-tab`・CLI `niwaterm new-tab --shell <id>`まで一気通貫で配線。プロファイル一覧を返す`niwaterm shell-profiles`/`GET /shell-profiles`も追加）
- [x] 「+」ボタン横にWindows Terminal風のドロップダウン（「⌄」ボタン）を追加し、新規タブ作成時にプロファイルを選べるUIを実装する（実機でのUI動作確認は未実施）

## AIによるブラウザ操作

CLIから内蔵ブラウザタブを操作できるようにする（PlaywrightのAPIのようにCLIから叩けることを目指す）。読み取り中心のMVPから始め、click/fillなどのDOM操作系は段階的に拡張する。
「GUI統合」節末尾の「HTML UIからアプリのAPIを呼び出せる」（HTML UI→niwatermアプリ側という逆方向の連携）とは別方向の機能であり競合しない。

- [x] bunメインプロセスがブラウザタブ（OOPIF）内でJSを実行し結果を受け取れる、非同期request/response基盤ができている
- [x] `niwaterm browser-navigate --tab <tabId> --url <url>` でブラウザタブのURLを遷移できる（Playwrightの`page.goto()`相当）
- [x] `niwaterm browser-get-text --tab <tabId>` でブラウザタブの表示内容をプレーンテキストで取得できる
- [x] `niwaterm browser-get-html --tab <tabId>` でブラウザタブのHTMLを取得できる
- [x] `niwaterm show-tab --tab <tabId>` で対象タブのワークスペース・タイルへ切り替え、タブをアクティブ化し、ウィンドウを前面化できる
- [x] 上記4コマンドが各種エラーケース（タブ不存在・対象タブがterminalタブ等）で適切なエラーを返すことを確認できている
- [x] `niwaterm browser-screenshot --tab <tabId> --out <path>` でスクリーンショットを取得できる
      既知の制約: 「表示中タブそのもの」ではなく「同じURLを新規に開いた場合の見た目」になる（DOM状態・ログイン状態・スクロール位置等は再現されない）。ElectrobunのWebviewTagElementにスクショAPIが無いため、Bun本体（v1.3.12+）の`Bun.WebView`で対象URLを裏で開き直して撮る設計のため
- [ ] スナップショット（操作可能な要素だけを抽出した簡易構造）を取得できるコマンド（`niwaterm browser-snapshot`相当）を追加する。cmuxの「Snapshot + Refs」戦略を参考に、DOM全体ではなくクリック・入力可能な要素の参照リスト（ref）のみを返すことで`browser-get-html`よりAIのトークン消費を抑える。click/fill実装の前提となる
- [ ] click・fill等のDOM操作系コマンドをCLIから叩けるようにする。要素指定はCSSセレクタと上記スナップショットのrefの両方に対応する（セレクタ指定は単純な操作で使いやすい、ref指定はスナップショット取得後の連続操作でトークン効率が良い。用途に応じて使い分けられるよう両方サポートする）
- [ ] 複数タブへの並行操作（同時に走る複数のexecBrowserJs呼び出し）が正しく相関IDで区別されることを確認できている
- [ ] ブラウザタブのURLがbun側の状態に同期されず、非アクティブワークスペース再アクティブ化時に初期URLへ巻き戻る既知の制約への対応（`did-navigate`受信時のURL書き戻し）
