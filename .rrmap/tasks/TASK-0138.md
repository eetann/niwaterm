アプリ終了時に**実行中だった**コマンドを、次回起動時にタブへ打ち直す（tmux-resurrect型）。プロセス自体を生かし続ける方式はTASK-0137で中止した。スクロールバックの復元は対象外。

## 方針

- 記録はシェル統合で行う。preexecでコマンドラインを記録し、precmdで消す。終了時に残っていたものが「実行中だった」コマンド
- 打ち直す条件（上から順に判定）
  1. `;` `&&` `||` `|` `$(...)` バッククォート・リダイレクトを含むコマンドは問答無用で対象外。denyリストを各セグメントに当てる方式より単純で、穴が無いため
  2. 内部denyリスト（`rm`/`mv`/`dd`/`sudo`/`git push`など。設定では外せない）に当たれば対象外
  3. ユーザー設定の許可リストに、単語単位の先頭一致で当たったものだけ打ち直す（`claude`は`claude --continue`に、`git log`は`git log --oneline`に当たる）。既定は空で、機能はオプトインになる
- 判定前に先頭の環境変数代入（`CLAUDE_CONFIG_DIR=~/.xxx claude`）を剥がす。打ち直すときは代入込みの元のコマンドラインをそのまま使う。値に`$(...)`を含む代入は条件1で除外される
- エイリアスや関数の中身までは見えないので、そこは許可リストを書く人の責任とし、ドキュメントに明記する
- 打ち直しはシェルへの入力として送る（`sendInitialCommand`と同じ経路）。終了後にシェルへ戻り、履歴にも残る

## 適用範囲

- レイアウトで組んだタブ: タブ設定のオプション（仮: `resumeRunningCommand`）を付けたタブだけが対象。打ち直せるコマンドが記録されていれば、レイアウトの`command`より優先する。無ければ`command`を実行する
- レイアウトを使わない（`restore`モードの）Board: 既定で自動に打ち直す。全体設定でオフにでき、Boardごとにもオン/オフを切り替えられる（Board単位の切り替え手段は実装時に決める。CLIを足すならcli-command-naming.mdに従う）

## 実装時の注意

- branch通知と同じく`niwa tab var set &!`で非同期に送ると、短いコマンドではset（preexec）とclear（precmd）が逆順に届き、記録が残りっぱなしになりうる。順序を保証する仕組みが要る
- tab varはサイドバー表示と同じ置き場なので、内部用の名前にして表示から外す
