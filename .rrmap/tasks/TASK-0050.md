原因・調査済みの内容はTASK-0049参照。electrobun 2.0.1へアップグレード

## config schema・CLI互換性の調査結果（2026-08-23）

npmのpackage.json・GitHubリリースアセット（`electrobun-artifacts.json`・`electrobun-core-win-x64.tar.gz`同梱の`native-devkit.json`・`api/config/ElectrobunConfig.ts`）・公式ドキュメント（`guides/migrating-to-v2`・`apis/cli/build-configuration`）を確認。

**低リスクな点**
- 2.0.1がバンドルするBunは1.4.0（TASK-0051参照）。現行の`bunVersion: "1.3.14"`上書きが不要になる
- `build.mainProcess`が新設され、デフォルトは`"cottontail"`に変わったが、`mainProcess: "bun"`を明示すればv1同様`src/bun/index.ts`をそのままメインプロセスに使える低リスクなブリッジパスがある
- CLIコマンド（`electrobun dev --watch`等）はほぼ互換維持。`--env=production`は`--env=stable`にリネームされたが、niwaterm側は未使用のため影響なし

**破壊的変更（要対応）**
- `build.bunVersion`はv1-only設定として廃止（「Hutch builds for the current host, and the exact Electrobun release supplies its bundled runtime versions」）。`electrobun.config.ts`から該当行を削除する
- `views.<name>.plugins`（Bunバンドラーへのカスタムプラグイン渡し）が完全に非サポートになった（「Function-valued bundler plugins cannot cross that boundary」）。niwatermが渡している2つのプラグインへの対応が必要:
  - `createMainviewAliasPlugin`（`@/*`エイリアス解決、bun-mainview-alias-plugin.ts）→ 新設の`views.<name>.alias`（`Record<string, string>`）で代替できる可能性が高いが、ドキュメント例は単一ファイルへのマッピングのみで、ディレクトリ丸ごとのプレフィックス解決に対応するかは未検証。実際に試して確認する必要がある
  - `bun-plugin-tailwind`（Tailwind CSS v4のビルド時変換）→ 代替オプションが存在しない。公式ガイド曰く「plugin transformが必要なフレームワークは自前でViteビルドを回して出力をコピーする」。`preBuild`スクリプトで`tailwindcss` CLIを直叩きしてCSSを生成し、`copy`で成果物を持ってくる方式への作り直しが必要になりそう

**次のアクション**: まず別ブランチ等でelectrobun@2を最小構成でインストールし、(1) `views.alias`で`@/*`エイリアスが期待通り解決できるか、(2) tailwindcss CLI直叩き方式でビルドが通るか、を小さく検証してから本格移行の要否・工数を見積もる。macOS・Windows双方での実機確認も必要（TASK-0049参照）。

## ブロッカー（2026-08-23、解除済み）

`bun add electrobun@2.0.1`が`bunfig.toml`の`minimumReleaseAge`（サプライチェーンアタック対策、公開から3日未満のバージョンをインストール禁止）でブロックされた。electrobun 2.0.1の公開日は2026-08-22。サプライチェーンアタック防止のため、25日以降に対応。

## Windows実機での移行結果（2026-08-25）

`bun add electrobun@2.0.1`でインストールし、`electrobun.config.ts`を新スキーマへ書き換え。Windows実機（`mise run win:sync` → `bun x electrobun dev`）でビルド・起動・PTY・タイル分割・niwaterm CLIでの疎通を確認し、フォーカスボーダー欠け（TASK-0049本体）が解消していることも確認済み。

**判明した実装内容**（懸念点の答え合わせ）:
- `views.<name>.alias`は`{"@/*": "./src/mainview/*"}`のようなプレフィックスマッピングをそのまま解決できた。`bun-mainview-alias-plugin.ts`は不要になり削除
- `views.<name>.jsx`オプションは2.xの型定義に存在しない。削除してtsconfig.jsonの`jsx: "react-jsx"`任せにしたところ問題なく動いた
- Tailwind CSSは想定通り`preBuild`でCLI直叩きが必要だった。`@tailwindcss/cli`を`devDependencies`に追加し、`scripts/build-tailwind.ts`（tailwindcss CLIで`.tailwind-build/index.css`を生成）→`build.copy`で`views/mainview/index.css`へ配置、`build.watch`で`src/mainview/index.css`をwatch対象に追加。`bun-plugin-tailwind`は削除
- `scripts.preBuild`は1スクリプトしか指定できないため、`write-app-variant.ts`と`build-tailwind.ts`をまとめる`scripts/pre-build.ts`を新設
- 副産物: electrobun 2.0.1は`launcher.exe`/`bun.exe`へのWindowsアイコン埋め込みを自前で成功させるようになった（ビルドログに`embedded Windows icon in launcher.exe`等が出る）。1.18.1のrcedit解決バグ（#429）の回避策として入れていた`scripts/embed-windows-icon.ts`・`postBuild`フック・`rcedit`依存が不要になったため削除（詳細: docs/known-issues/windows-app-icon-not-showing.md）

**未検証**: macOS実機。WSL環境での作業だったためWindows実機のみで検証した。macOS側は`build.mac`のスキーマ自体はほぼ1.x互換に見えるが、実際にビルド・起動・アイコン反映を確認していない。次にmacOS実機を触るタイミングで要検証
