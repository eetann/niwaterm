サイドバーにブランチ・AIエージェントの状態（agent/agent_status/agent_status_text）が表示されなくなっていた。

## 原因1: CLIコマンド改名の追従漏れ（主因）

`5e03225 refactor!: CLIコマンドをリソース単位のサブコマンド体系へ統一` で
`niwaterm set-var` は `niwaterm tab var set` へ改名されたが、追従できていない箇所があった。

- `contrib/shell-integration/niwaterm.{bash,zsh,fish,ps1}` — 4本とも旧名のまま（ブランチ表示が死ぬ）
- `docs/build/windows-build.md` の例 — 旧名のまま
- **利用者の`~/.claude/settings.json`に導入済みのhooks** — 旧名のまま
  （リポジトリの`contrib/agent-integration/claude-code/hooks.json`自体は5e03225で更新済み。
  導入済みのコピーは手動でしか追従できない）

hooks・シェル統合はどちらも `>/dev/null 2>&1` で出力を捨てるため、
`Command not found: set-var` が無言で握り潰され、症状として「何も表示されない」だけが残っていた。

## 原因2: Board導入で表示対象が代表タブ1つに絞られた（副因）

`f962a6d feat: サイドバーをBoard階層対応のデザインに刷新する` 以前は、サイドバーが全Tile・全Tabを
行として列挙し、タブごとにagent状態を出していた。刷新後はBoardあたり1行になり、
`findRepresentativeTabId()`（フォーカス中タイルのアクティブタブ）の変数しか見ない。

そのため、非フォーカスタイル・非アクティブタブで動いているエージェントの状態は表示されない。
「1つのBoard=1つの独立した作業」という設計意図（ADR 0006後の再設計）どおりではあるが、
1つのBoardの中でエージェントを別タブに置く使い方だと従来より見えなくなっている。

## 対処

- [x] `contrib/shell-integration/*` 4本を `niwaterm tab var set branch` へ修正
- [x] `docs/build/windows-build.md` の例を新コマンド名へ修正
- [x] 利用者側の`~/.claude/settings.json`（home-manager管理、実体は`~/dotfiles/.claude/settings.json`）を
      `contrib/agent-integration/claude-code/hooks.json` の内容へ更新する（リポジトリ外なので要ユーザー対応）
- [x] 原因2への対応: Board内の全タブを走査し blocked > working > idle で最も目立つ状態を1行に集約（findBoardAgent）
- [x] `.claude/rules/cli-command-naming.md`へ`contrib/`配下の同期漏れ防止を追記（再発防止）
- [ ] Windows実機での表示確認（`mise run start`でniwaterm-wipを起動して目視）
