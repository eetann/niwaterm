Boardに付ける独自の作業段階を、識別子・UI文言とも「ステータス」から「フェーズ」へ改名した。

## なぜフェーズにしたか

サイドバーのBoard行には別物の「status」が既に3つ同居していた。エージェントの稼働状態
（`agent_status`タブ変数。working/blocked/idleで勝手に変わる）、Board行の下に展開する
ステータスライン（Neovimのwinbar相当の情報行）、そして今回の作業段階。さらにMILESTONE-0011で
ステータスバーが来る。plan→implement→reviewという順序を人が明示的に進める概念は、
「現在の状態」一般を指すstatusより「フェーズ」の方が意味が正確で、上の3つとも衝突しない。

docs・JSDoc・コミットメッセージが既に「作業フェーズ」と書いていて識別子だけstatusという
二重帳簿状態だったのも決め手。

## 互換を切った判断

旧`board.statuses`・`board status`コマンド・`set-board-status:`アクションは残さず削除した。
未リリース（タグ無し）で、`contrib/agent-integration`のhooksが呼ぶのは`tab var set agent_status`
だけなので、利用者のコピー済み設定が壊れる経路が無い。永続化（workspaces.json）も旧キーの
読み替えを入れていない。改名時点で実データに値が1件も入っていなかったため。

## CLIの形

`niwaterm board status <id> --clear`（1コマンドにset/show/clearを詰めた形）から、
`niwaterm board phase set/clear/show`のサブリソース形へ揃えた。`tab var get/set`と同じ構成で、
cli-command-naming.mdの`<resource> <verb>`にも乗る。

## 引き継ぎ

- `~/.config/niwaterm/niwaterm.config.ts`の`board.statuses`は`board.phases`へ手で直す必要がある
  （未知キーは黙って無視されるので、直すまで候補が空になる）
- `BoardStatusEntry`（workspace-managerのBoard一覧エントリ型）はフェーズとは別概念なので改名対象外
