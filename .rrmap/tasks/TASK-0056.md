TASK-0050（electrobun 2.0.1・Bun 1.4.0アップグレード）の実機検証中（2026-08-26）に発覚。

## 症状

niwaterm-daily（`niwa run start:daily`）がdevモードで起動中に、niwaterm-wip（`mise run start`）を
起動しようとすると、ビルドが `[electrobun] Waiting for the project build lock...` のまま進まなくなる
（数分待っても完了しない）。dailyを停止すると即座に解消してwipが起動できる。

## 原因

electrobun 2.0.1でプロジェクトルート直下に`.hutch/locks/`が新設され、reader/writerロックらしき
排他制御が入った（`.gitignore`にも`.hutch/`が追加済み: 5421e54参照）。`.hutch/locks/electrobun-readers/`
配下に実行中devインスタームのリース(`.lease`)ファイルが作られ、これが起動中は排他ロックされたまま
（`Get-Content`で「別のプロセスがファイルの一部をロックしています」エラーになる）。新しいdevプロセスの
起動（ビルド）は、既存リーダーがいる間はブロックされるように見える。1.18.1にはこの仕組みが無かった。

## CLAUDE.mdの前提との齟齬

CLAUDE.mdの「niwaterm-wipとniwaterm-dailyは...appSupportDir・IPCソケット・WSLブリッジポートが分離
されているため、同時に起動しても干渉しない」という記述はランタイム（実行時のリソース分離）の話で、
これ自体は今も正しい。今回問題になっているのはビルド・起動シーケンス側の排他制御で、別レイヤーの制約。

## 調査結果

- ロックを無効化する公式フラグは存在しない。`HUTCH_ELECTROBUN_BUILD_LOCK`という環境変数が
  実体（`blackboardsh/hutch`、Zig実装）に存在するが、これは無効化用ではなく「再帰ビルド検知用の
  内部マーカー」（親プロセスが子プロセスに伝播し、同じproject_rootに対して再度ロックを取ろうと
  したら`RecursiveElectrobunBuild`エラーで即失敗させる仕組み）。手動でセットしても無効化にはならない
- reader lease（起動中インスタンスの生存確認、`.hutch/locks/electrobun-readers/*.lease`）はOSの
  advisory file lockで実装されており、正常終了・クラッシュ問わずOSが自動解放するため、writer側が
  次回ロック取得時にstaleなleaseを自動検出・削除する設計になっている
  （`blackboardsh/hutch`の`build-lifecycle-lock.test.js`で検証済みの挙動）
- **実機で新たに判明した別の穴**: Windowsのプロセスは親をkillしても子孫は自動終了しない。
  `electrobun.cjs → hutch.exe → hutch-engine.exe`という親子関係があり、ビルド中に上位プロセスだけ
  強制終了すると`hutch-engine.exe`が孤児として残り、`electrobun-build.lock`（writer lock）を
  握ったまま解放されない。reader leaseの自動クリーンアップは機能するが、writer lock自体が
  孤児プロセスに握られたケースは自動回復しない。復旧には`hutch-engine.exe`を手動でkillする必要が
  ある（`mise run win:stop`のプロセス名フィルタに`hutch`を追加済みで対応可能。個別停止の
  `win:stop:mine`は`ExecutablePath`ベースの絞り込みなのでhutch関連プロセスまでは追えていない）

## 対応（採用した回避策）

wip・dailyの実体そのものを別のgit worktreeに分離した（gtrで管理。wip=devブランチの追加worktree、
daily=mainブランチのメインワークツリー）。project_root自体が別になるため`.hutch/locks/`が競合せず、
同時起動できるようになった。Windows側の同期・起動・停止・dev→main取り込みまで`mise.toml`の
タスクとして自動化済み（`start`/`win:sync`/`win:stop:mine`/`daily:merge-dev`等。`start`は現在の
ブランチからwip/dailyを自動判定する）。vendor/（gitignore対象、Windows向けビルド成果物）も
worktree間でコピー同期する仕組みを追加した。詳細はCLAUDE.md・docs/build/windows-build.md参照。
