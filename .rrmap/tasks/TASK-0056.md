TASK-0050（electrobun 2.0.1・Bun 1.4.0アップグレード）の実機検証中（2026-08-26）に発覚。

## 症状

niwaterm-daily（`niwa run start:daily`）がdevモードで起動中に、niwaterm-wip（`mise run start`）を
起動しようとすると、ビルドが `[electrobun] Waiting for the project build lock...` のまま進まなくなる
（数分待っても完了しない）。dailyを停止すると即座に解消してwipが起動できる。

## 原因

electrobun 2.0.1でプロジェクトルート直下に`.hutch/locks/`が新設され、reader/writerロックらしき
排他制御が入った（`.gitignore`にも`.hutch/`が追加済み: 5421e54参照）。`.hutch/locks/electrobun-readers/`
配下に実行中devインスタームのリース(`.lease`)ファイルが作られ、これが起動中は排他ロックされたまま
（`Get-Content`で「別のプロセスがファイルの一部をロックしています」エラーになる）。新しいdevプロセスの
起動（ビルド）は、既存リーダーがいる間はブロックされるように見える。1.18.1にはこの仕組みが無かった。

## CLAUDE.mdの前提との齟齬

CLAUDE.mdの「niwaterm-wipとniwaterm-dailyは...appSupportDir・IPCソケット・WSLブリッジポートが分離
されているため、同時に起動しても干渉しない」という記述はランタイム（実行時のリソース分離）の話で、
これ自体は今も正しい。今回問題になっているのはビルド・起動シーケンス側の排他制御で、別レイヤーの制約。
