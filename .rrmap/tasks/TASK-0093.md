`git worktree list --porcelain`のパースと、リポジトリルート・メインワークツリーの解決を担う層を作る。
以降の new / open / remove / UI が全てここを経由する。

- 取れるようにする情報: ワークツリーのパス、ブランチ名、HEAD、detached、locked、prunable、メインかどうか
- ワークツリーの置き場所（`../<repo>-<branch>`なのか`.worktrees/`配下なのか）の既定と設定での上書き
- `niwaterm worktree list`はniwatermの外からも使えるようにする（Board未使用でも単体で成立させる）
- gitが無い・リポジトリ外・worktree未対応バージョンといった異常系の扱いを決める

## 決めたこと

**gitの呼び出しはCLIプロセスに置く**（`packages/cli/src/worktree/`）。アプリ側へ寄せてIPC越しにすると
「アプリ未起動のターミナルから一覧が引けない」という要件を満たせないため。後続のUI（popup）が
アプリ側で一覧を要るようになった時点で、src/bunへ移すかIPCを足すかを判断する。

**置き場所テンプレートの優先順位**は
`<repoRoot>/.niwaterm/config.ts` → `~/.config/niwaterm/niwaterm.config.ts` → git configの
`niwaterm.worktree.dir` → 既定値`../${repo}@${branch}`。git configを一番弱くしたのは、niwatermの
設定の正本が`niwaterm.config.ts`であり、git config側はniwatermを入れていない環境とも設定を
共有したい人向けの補助口という位置づけのため。

プロジェクトローカル設定は、レイアウトプリセットと違ってcwdからの上向き探索をしない。
置き場所はリポジトリ全体の方針でワークツリーごとに変わらないので、メインワークツリー直下だけを見る。

## 後続タスクへの引き継ぎ

- `resolveWorktreePath({ repoRoot, branch })`が置き場所の解決の入口。戻り値の`source`で
  どの設定で決まったかが分かるので、`worktree new`のメッセージや切り分けに使える
- 置き場所の設定は型だけ`@niwaterm/config`へ入れて解決経路も通してあるが、実際に作成へ使うのは
  TASK-0094以降。`worktree list`はこの設定を参照しない
- `-z`付きporcelainを既定にしている。lockの理由が非ASCIIのとき、行区切りだとgitがC-quoteした
  バイト列（`"\344\275..."`）で返すが、`-z`なら生のUTF-8で取れる
