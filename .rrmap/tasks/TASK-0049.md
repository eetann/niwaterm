TASK-0047（画面いっぱいに描画されるとした数行が見えない）からの派生。ユーザー報告:「普通にwin:startで起動してタイルが1つだけのとき、フォーカスのあるタイルにあるボーダー表示が右と下だけでないのも同じ理由だと思う(上と左はちゃんと出る)。本来ならタイル1つなんだからボーダーは上下左右全部見えるはず」。

TASK-0047の方は「新規タイル・アプリ起動復元時にPTYへ実際のサイズと異なる値を渡し、その後のSIGWINCHが取りこぼされる」というPTYサイズ起因のバグと特定・修正できたが、こちらは`.tile.focused`のoutline（`src/mainview/index.css`）というDOMレイアウト側の話で、原因が別物だった。初回調査時（TASK-0047のセッション内、2026-08-23）は再現できなかったが、その後ユーザーから「まだ直ってない」とスクリーンショット付きで再指摘があり、実機で再現・原因特定まで到達した。

## 原因（判明済み）

niwaterm固有のCSSバグではなく、**Electrobun本体（1.18.1）のWindows/WebView2まわりの既知バグ**。

- `BrowserWindow`が作るデフォルトwebview（`autoResize: true`のfull-sizeビュー）は、WebView2コントローラ生成の非同期コールバック内で、ウィンドウ作成時に一度だけキャプチャした**古い「外枠サイズ」**（タイトルバー・ボーダー込みの寸法）をそのまま`put_Bounds`に渡していた
- 一方、通常の`WM_SIZE`ハンドラは`GetClientRect`で正しい「クライアント領域」（実際に描画できる内側の領域）を計算し直す
- WebView2コントローラは非同期に生成されるため、ウィンドウの最初の`WM_SIZE`（正しいクライアント矩形が判明する機会）が発生した時点ではまだコントローラが存在せず、そのリサイズ通知は捨てられる
- 結果、起動直後だけwebviewがクライアント領域より右・下に数十pxはみ出た状態で固定され、`.tile.focused`のoutline（`outline-offset: -1px`）が右・下だけクリップされて見えなくなる。手動でウィンドウをリサイズすると本物の`WM_SIZE`が発火し正しい値に更新されるため直る、という実機での挙動と一致する
- 実験で確認: `body`要素にborderを付けても同じ現象（右端・下端だけ欠ける）が再現し、`.tile`固有の問題ではないことを確認済み
- `mainWindow.setSize()`によるトグルで強制リサイズを起こす修正案を試したが、**タイミングが早すぎて効果がなく**、むしろ`.tile`要素が画面外へ押しやられる深刻なレイアウト崩壊を引き起こしたため撤回した（後述のGitHub issueの解析で、コントローラがまだnullの間はWebView2側がリサイズ要求を黙って無視することが判明し、この副作用の理由も裏付けられた）

**参照issue**: [blackboardsh/electrobun#431](https://github.com/blackboardsh/electrobun/issues/431)（本家）、重複扱いの[#462](https://github.com/blackboardsh/electrobun/issues/462)。どちらも同じ症状・同じ原因をコミュニティが解析済みで、上記の説明はそこでの解析と一致する。

**修正状況**: `v2.0.1`（コミット`e04eff1a` "fix(windows): harden native runtime and packaging"、`package/src/native/win/nativeWrapper.cpp`）で修正済み。`initialWebView2Bounds`という関数が新設され、full-sizeビューの場合はコントローラ作成コールバック内で改めて`GetClientRect`を呼び直すようになっている。niwatermは現状`electrobun@1.18.1`を使用中（`package.json`は`"latest"`指定だが実際にインストールされているのは1.18.1）。

## 対応方針（未着手・要検討）

1. **electrobun 2.0.1へアップグレード**: 本家の正式修正を取り込める。ただし1.x→2.xのメジャーアップグレードで、コミット履歴に"retire legacy CLI from npm package"「runtime-neutral main SDK」など大きな変更が見える。`electrobun.config.ts`のスキーマ変更・CLI(`electrobun dev`等)の互換性を先に確認する必要がある。macOS側の実機確認も要る
2. **アプリ側でワークアラウンドを実装**: issue #431で共有されていた回避策（`mainWindow.webview.on("dom-ready")`後に`bun:ffi`でuser32.dllの`GetClientRect`→`SendMessageW(hwnd, WM_SIZE, ...)`を直接叩き、正しいクライアントサイズでネイティブ側の`WM_SIZE`回復パスを走らせる）をWindows限定で実装する。electrobun本体のバージョンは上げずに1.18.1のまま適用できる

どちらを採るか、またはアップグレードを別途本格検討するかは未決定。次に着手するときはここから始める。

## 解決（2026-08-25）

方針1（electrobun 2.0.1アップグレード、TASK-0050）を実施。Windows実機で1タイルのみの状態のフォーカスボーダーが上下左右すべて表示されることをユーザーが目視確認し、解消を確認した。詳細な移行作業の記録はTASK-0050参照。
